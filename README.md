# mietermeter
## Requirements

*   **Docker**
*   **Git**

## Quick Start

1.  **Clone repo:**
    ```bash
    git clone https://github.com/nanocraftmr/mietermeter
    cd mietermeter
    ```

2.  **Configure Environment Variables:**

    *   Edit the `.env` file to set your environment variables:

        ```
        HDGIP1="your_hdgip1_address"       # Replace with the actual HDG IP address for Brenner 1
        HDGIP2="your_hdgip2_address"       # Replace with the actual HDG IP address for Brenner 2
        SUPABASE_URL="your_supabase_url"  # Replace with your Supabase URL
        SUPABASE_KEY="your_supabase_key"  # Replace with your Supabase API key
        CAMERA="rtsp://USERNAME:PASSWORD@IP_ADRESSE:PORT" # Replace with RTSP login, IP and Port of Camera

        # Optional: QUNDIS Q log 5.5
        QLOG_ADDRESS="<QLOG-BLUETOOTH-MAC>"
        QLOG_CHANNEL="5"
        SUPABASE_HEATING_TABLE="heating_meter_readings"

        # Optional: Fronius PV lifetime counters → public.pv_readings
        # One IP or many (comma / semicolon / space separated). No code change needed.
        FRONIUS_IPS="192.168.0.85,192.168.0.104"
        FRONIUS_READING_HOUR="23"
        SUPABASE_PV_TABLE="pv_readings"
        ```

    Docker Compose loads this file only when the container starts. Secrets such
    as `SUPABASE_KEY` are deliberately not copied into the image and therefore
    do not appear in the `docker-compose build` output.

3.  **Build the Docker Image:**

    ```bash
    docker-compose build
    ```

4.  **Start the Application:**

    ```bash
    docker-compose up -d
    ```

## QUNDIS Q log 5.5

The application can collect QUNDIS heat cost allocator readings through the
Q log 5.5 Bluetooth Serial Port service. One test collection runs whenever
the application starts. Further collections run every day at 08:00 and 20:00.
Each meter ID is accepted only once per collection.
There is no default Bluetooth address: set `QLOG_ADDRESS` to the MAC printed
by `bluetoothctl devices`, otherwise heating collection remains disabled.

Each collection waits for one complete radio cycle. The first received meter
ID marks the beginning of that cycle. When the same ID appears again after at
least ten minutes, all unique meters collected in between are saved. A hard
timeout ends the collection after 16 minutes.

The Q log switches itself off after approximately five minutes without a
Bluetooth connection. It must therefore be switched on shortly before a
scheduled collection. If the process is restarted, switch on the Q log before
testing the connection.

### Pair Bluetooth on the Raspberry Pi

Install the Bluetooth tools on the Docker host:

```bash
sudo apt update
sudo apt install -y bluez
```

Switch on the Q log and pair it on the host:

```bash
bluetoothctl
```

Enter these commands in `bluetoothctl`, replacing the placeholder with the
address reported by `bluetoothctl devices`:

```text
power on
agent NoInputNoOutput
default-agent
scan on
pair <QLOG-BLUETOOTH-MAC>
trust <QLOG-BLUETOOTH-MAC>
info <QLOG-BLUETOOTH-MAC>
quit
```

Confirm that the Serial Port service uses RFCOMM channel 5:

```bash
sdptool browse <QLOG-BLUETOOTH-MAC>
```

The output should contain `Bluetooth Serial Port` and `Channel: 5`.
Pairing is done on the host, not inside the container. The Compose
configuration uses host networking, `NET_ADMIN`, `NET_RAW` and an unconfined
seccomp profile. The last setting is required because Docker's default seccomp
profile blocks `AF_BLUETOOTH`; it reduces the isolation of this container.

After changing `.env`, recreate the container (an image rebuild is not needed):

```bash
docker-compose down
docker-compose up -d
docker-compose logs -f hdg_app
```

Verify that the container can create a Bluetooth socket:

```bash
docker-compose exec -T hdg_app python -c \
  "import socket; s=socket.socket(socket.AF_BLUETOOTH, socket.SOCK_STREAM, socket.BTPROTO_RFCOMM); print('AF_BLUETOOTH OK'); s.close()"
```

With the Q log switched on, test one actual reading:

```bash
docker-compose exec -T hdg_app python -c \
  "import os; from worker.qlog import collect_readings; print(collect_readings(os.environ['QLOG_ADDRESS'], collection_seconds=30, minimum_cycle_seconds=0))"
```

### Supabase table

Run the following SQL once in the Supabase SQL Editor:

```sql
create table if not exists public.heating_meter_readings (
    id bigint generated by default as identity primary key,
    collection_id uuid not null,
    captured_at timestamptz not null default now(),
    source_mac text not null,
    qlog_address text not null,
    meter_id text not null,
    manufacturer text not null,
    version smallint not null,
    device_type smallint not null,
    access_number smallint not null,
    current_value integer,
    setpoint_value integer,
    setpoint_date date,
    meter_time timestamp without time zone,
    battery_low boolean not null,
    status smallint not null,
    error_date date,
    rssi_dbm smallint,
    unique (collection_id, meter_id)
);

create index if not exists heating_meter_readings_meter_time_idx
    on public.heating_meter_readings (meter_id, captured_at desc);
```

`collection_id` groups one scheduled run. Its unique constraint provides a
second safeguard against storing the same heater twice in one run.

Use a Supabase service-role key only on this private Raspberry Pi and never in
a browser or public repository. If Row Level Security is enabled and an anon
key is used, an appropriate insert policy is required; a service-role key
bypasses RLS.

Stored fields include the current allocation value, billing-date value and
date, meter clock, low-battery warning, device status, error date and received
signal strength. Q caloric 5.5 devices provide only a low-battery warning, not
a battery percentage.

## Fronius PV readings

Every local day at `FRONIUS_READING_HOUR` (default **23:00**) the app reads each
IP in `FRONIUS_IPS` and upserts one row per device into Supabase
`public.pv_readings`.

| Column | Source |
| --- | --- |
| `device_name` | `GET /solar_api/v1/GetInverterInfo.cgi` → `CustomName` (e.g. `PV Esterhazy`) |
| `ip_address` | IP from `FRONIUS_IPS` |
| `read_at` | API `Head.Timestamp` |
| `total_production` | `GetInverterRealtimeData.cgi?Scope=System` → `TOTAL_ENERGY` (Wh) |
| `total_feed_in` | `GetMeterRealtimeData.cgi?Scope=System` → `EnergyReal_WAC_Sum_Produced` (Wh) |
| `total_grid_import` | same meter call → `EnergyReal_WAC_Sum_Consumed` (Wh) |

Values are **lifetime counters** (raw Wh), not day deltas. Day energy is
`today − yesterday` on these totals.

Create the table once in the Supabase SQL Editor if it does not exist yet:

```sql
create table public.pv_readings (
  id bigint generated always as identity not null,
  device_name text not null,
  ip_address inet null,
  read_at timestamp with time zone not null,
  total_production numeric null,
  total_feed_in numeric null,
  total_grid_import numeric null,
  created_at timestamp with time zone not null default now(),
  constraint pv_readings_pkey primary key (id),
  constraint pv_readings_device_read_at_key unique (device_name, read_at)
) TABLESPACE pg_default;

create index IF not exists pv_readings_read_at_idx
  on public.pv_readings using btree (read_at desc) TABLESPACE pg_default;
```

Manual one-shot test inside the container (after `FRONIUS_IPS` is set):

```bash
docker-compose exec -T hdg_app python -c \
  "from main import collect_and_save_pv_readings; print(collect_and_save_pv_readings())"
```

## Troubleshooting

*   **Environment Variables Not Set:** If you see an error message about missing environment variables, double-check your `.env` file and make sure the keys and values are correct.  Also, ensure the .env file is in the same directory as `docker-compose.yml`. After changes restart the docker (docker-compose down, then up).

*   **Bluetooth timeout:** Ensure that the Q log is switched on, trusted on the
    host, not connected to ACT46 or another computer, and that its address in
    `.env` is correct.

*   **Not all meters received:** Check that the Q log remains connected for the
    complete 16-minute collection and that the missing meter is transmitting.

*   **Other Errors:** look up the docs or create an issue
